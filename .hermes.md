# Hermes Ops — Phases 0, 1, and 2

Phase 0 is intentionally dependency-light and service-free:

- `packages/contracts`: versioned evidence manifest and validation
- `packages/policy`: deterministic fail-closed policy evaluator

Phase 1 adds the PostgreSQL schema and queue primitives in `packages/db`:

- ordered SQL migrations for tasks, jobs, generic agent_runs, evidence, audit_events
- typed row/status definitions and a safe `FOR UPDATE SKIP LOCKED` claim query
- retry/backoff and stale-lock recovery pure helpers with bounded attempts
- idempotency guidance

No DB driver, GitHub SDK, CodeRabbit API, Devin API, HTTP server, credentials,
or network calls are introduced in Phase 1; tests do not require a live database.

Phase 2 adds adapter contracts in `packages/adapters`:

- GitHub webhook HMAC-SHA256 verification (strict `sha256=` format, raw-payload
  input, constant-time comparison, secrets never logged) and a bounded
  in-memory delivery-id dedupe shaped for later DB-backed replacement.
- CodeRabbit normalization into the contracts `CodeRabbitFindings` shape,
  preserving only id/severity/resolved and rejecting malformed/untrusted
  instruction fields.
- generic `CodingAgentAdapter` interface (capabilities/createRun/getRun/
  sendFeedback/cancelRun) and shared `AgentRun` types.
- `DevinAdapter` with injected transport, explicit normal default, bounded
  budget, structured output required, and risk-based model selection
  (glm-5-2 default, swe-1-7 only for HIGH/CRITICAL); fast mode never
  auto-selected.

No HTTP server, network calls, credentials, or real GitHub/CodeRabbit/Devin
API calls are introduced in Phase 2; transports are injected and tests use
in-memory doubles.

Phase 3 (OPS-004) adds the `hermes/policy-gate` CLI in `packages/gate`:

- `hermes-policy-gate` bin wrapping the pure contracts + policy evaluator.
- Local deterministic execution only: no GitHub SDK, HTTP, database, agent
  calls, credentials, or network.
- Strict argv: required `--manifest`, `--head-sha` (40 lowercase hex),
  `--policy-version` (semver); optional `--output`. Rejects unknown/missing
  args and unsafe paths (manifest must be a readable regular file; output must
  not be a directory).
- Emits stable machine-readable JSON with `decision`, `reasonCode`,
  `policyVersion`, `evidenceIdentity` (when available), `detail`; no full
  manifest/source content.
- Exit 0 PASS, 1 policy failure / invalid evidence, 2 usage / operational
  error. Never prints secrets or raw JSON on errors.
- Subprocess tests for pass, stale/mismatched/CI/finding failures, malformed
  input, usage, stable output, and exit codes.
